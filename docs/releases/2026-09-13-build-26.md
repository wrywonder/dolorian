## Production database

The hosted ledger matched the 20 earlier repository migrations. A dry run listed
exactly these three pending migrations, which were then applied successfully:

1. `20260908001000_harden_hangout_venue_creation.sql`
2. `20260908020000_rsvp_note_privacy.sql`
3. `20260912000000_plan_intent_and_schedules.sql`

Deployment used the existing Supabase CLI credential and the explicit Village
project `ymmvdepipjmqlustbdkr`. Seeds, custom roles, and vault changes were excluded.
No fixture rows, test accounts, or sample plans were added to production.

Read-only production checks passed for all 23 ledger entries, the four new plan
columns, the three new authenticated RPCs and anonymous restrictions, venue
insert permissions, RSVP-note privacy, plan ownership, undated plans, Saturday
soccer, weekday camp hours, and daylight-saving gaps/folds. Existing rows retain
their legacy semantics.

The EAS production environment targets the confirmed Village project and uses an
`anon` client key. API probes returned the expected anonymous permission denials
for plan visibility and `plan_shared_by`; these establish the exposed endpoint
and access boundary, not a signed-in end-to-end user journey.

## Verification and release mechanics

Fresh release checks: `npm install` made no dependency changes, typecheck passed,
all 107 Node tests passed, and the signed production iOS build succeeded. The
previous [Plans pass](../plans-improvement-pass.md) documents the 11 successful
native fixture flows, both platform exports, and local SQL regression coverage.

The first submission attempt was rejected before scheduling because Expo's CLI
testing-notes option requires an Enterprise plan. Submission succeeded without
that option; the exact notes below were saved directly through Apple's API.
An expired browser session did not block release: the existing Expo-managed
submission credential was used in memory through the installed EAS client and
Apple's API. No new credential was created, printed, or saved to this repository.

The final Apple read confirmed beta review `APPROVED` and `IN_BETA_TESTING`
externally as well as internally. Group membership and saved notes were checked
through separate reads.

Physical-device behavior, Android runtime, full VoiceOver, push arrival, and
installation on each tester's phone remain outside this release verification.
Testers should update before trying the new explicit intent and weekly schedules.

## What to test

Plans is simpler: start with a name, choose a date or leave it to decide, find a
place, and invite connections or specific friends. Try a house hangout or park
birthday, Saturday soccer, and weekday camp with daily hours. Supporting links
keep Going/Maybe; signup activities use Signed up/Considering. Please check
sharing with the keyboard open, editing and rereading links, and saving family
details. Update to this build before testing weekly schedules. Send feedback
through TestFlight or beta@withvillage.app.
